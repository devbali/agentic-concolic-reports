# results3 gen2 — mock-layer bug fixes (2026-08-19)

Gen1 (all six endpoints' corpora, archived to
`../trash/results3_gen1_20260819/` with every derived artifact: coverage
summaries, exploration summaries, REPORTs, extraction outputs, reference
diff) was invalidated by two mock-layer bugs Bali spotted in the extracted
SQL. Gen2 = same mock files, fixed, corpora regenerated from scratch
(notifications_index first). The fixes live in each endpoint's private
`concolic_targets.rb` (footer + marked blocks); nothing in `src/` changed.

## Bug 1 — `AND (1=0)` narrowing every association query

`symbolic_instance` pinned `@new_record = true` on every symbolic
representative. Rails 5.2 `CollectionAssociation#scope` runs
`scope.none! if null_scope?` where `null_scope?` is
`owner.new_record? && !foreign_key_present?`
(`collection_association.rb:286-294`), and `none!` is literally
`where!("1=0")` (`query_methods.rb:736`). So every collection-association
SQL on a symbolic owner carried `AND (1=0)` — silently narrower than the
app's real query. Blast radius (gen1): 440/440 notifications_index dumps,
13,620/18,688 posts_show, 12/26 people_show.

**Fix (Bali directive: "it should just be symbolic, we should explore both
paths"):** `persisted?`/`new_record?` on a representative is now a seeded,
PC-recorded boundary decision `<base>_persisted` (default seed: persisted
— the side every query-returned row inhabits), via the SYM_DECISION
explicit-compare idiom since Ruby cannot hook bare truthiness. DSE can
flip the seed; the unpersisted side's `1=0` scopes / nil `to_param` are
then labeled by their own `_persisted == False` PC instead of leaking
unlabeled into every run. `@new_record` mirrors the seed.

Known consequences to watch per endpoint: on the persisted side (default),
`Comment#mentioned_people`-style `if persisted?` sites now take the
association branch (mentions SQL) rather than the `people_from_string`
text-parse branch gen1 always took — comments_index/posts_show's mention
seeding machinery partly idles until revisited.

## Bug 2a — finder kwargs dropped ("WHERE unavailable" notes)

The interceptor wrapper (`call_interceptor.rb:107`) captures
`|*splat_args, **kwargs|`; under JRuby/Ruby-3 keyword semantics,
`find_by(guid: x)` lands wholly in `kwargs`, and the param-binding loop
resolves Rails' `*rest`-signature finders (`find_by(*args)`) as
`kwargs[:args]` → nil. The conditions hash never reached the mock, so
`class_finder_sql` rendered the honest fallback ("WHERE unavailable ...
args=nil") and extraction kept unresolved `_SYM_RESULT_*` placeholders
instead of folding producer joins. Affected every keyword-called finder:
`Core::ClassMethods#find_by`, `FinderMethods#find_by`, the whole
`mention_lookup_*` family (157/237 gen1 people_stream dumps, plus
posts_show and comments_index).

**Fix:** footer module `ConcolicKwargsToPositional` prepended to
`ActiveRecord::Base.singleton_class` and `ActiveRecord::Relation` converts
keyword calls to `find_by`/`find_by!`/`exists?` back into Ruby-2-style
trailing positional hashes before method lookup reaches the interceptor's
`define_method`. No `src/` change (the interceptor's own param binding is
still kwargs-blind — candidate to raise upstream).

## Bug 2b — `render_relation_sql` crash on association scopes

arel-9 `Casted` nodes have `#val`, not `#value` — `collect_binds` raised
`NoMethodError` on any relation carrying one (association scopes with
symbolic owner keys build `Casted` via `build_quoted`), losing the whole
note to `sql_for`'s rescue fallback (`"Reshare query
(render_relation_sql failed: ...)"`, e.g. gen1 people_stream `find_by_2`
= `post.rb:138 reshare_for`). Two-part fix:

- `collect_binds` no longer collects `Casted` at all: it renders INLINE
  via `ToSql#quoted`, never as a `?` placeholder, so collecting it would
  misalign every later `?`↔bind pairing (the bind-rotation bug class).
- New footer visitor `ConcolicSymbolicToSql` (subclass of
  `Arel::Visitors::ToSql`) renders symbolic values as `$$(name)` inside
  `#quoted`, so inline-rendered Casted/Quoted symbolic values match the
  note convention instead of crashing `connection.quote`.

## Also fixed this session (pipeline, not mocks)

- The gen1 extraction's universal `subsume_ran: false` was a leaked
  `JAVA_TOOL_OPTIONS=-Xmx1200m` killing the blockaid JVM (rc=1) — unset in
  the extraction wrapper; see memory `oom-safe-heavy-jobs`.
- Heavy python/JVM jobs now run detached under
  `systemd-run --user -p MemoryMax=...` so overruns kill the cgroup, not
  the session (two kernel-OOM session kills on 2026-08-18).
