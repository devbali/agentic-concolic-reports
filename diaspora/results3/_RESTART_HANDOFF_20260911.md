### Name-boundary root cause ANSWERED (2026-09-14 19:25, `docs/NAME_BOUNDARY_PLAN_20260914.md`, 663 lines)
**It is NOT Z3.** Z3 accepts the runtime's name verbatim (`Int('len(X)')` → sat). The rename is forced by `concolic_engine/solver.py` transporting terms as **Python source text** rebuilt with `exec`/`eval`: `exec "len(X) = Int('len(X)')"` → SyntaxError (assign to a call), `eval "len(X) > 3"` → NameError (`len` is a builtin). `run.py:366-393` emits declarations as Python assignments; `ruby_runtime/int.rb:91` interpolates the name into Python-parseable text (its own comment says "a valid Z3/**Python** unary expression"). The mocks are consistent; the second dialect appears one stage later, in the only consumer that reuses Python's parser as its SMT parser.
**Scale:** `len(X)` is the ONLY non-Python-identifier name either runtime mints (600-dump scan: sole shape `*(*)`, 5,818 occurrences, zero others), from **2 lines** (`ruby_runtime/list.rb:68`, `py_runtime/list_.py:94`) — and it has spawned **48 copies of `fix_len_names`, 15 semantically distinct**, plus 13 of `canonicalize_ordinals`, across 150 files. **Nothing in `src/` depends on `SYM_LEN_` semantically** (all occurrences are docstrings or regexes accepting both). `git log -S` finds no commit: the rename has never existed in `src/`.
**A parse failure returns `unsat`** — "infeasible", the direction that manufactures false completeness; `coverage.py:2367`'s tautology probe is what turns that into `truncated=True` instead of a wrong answer.
**Accidental vs essential:** the length spelling is accidental/syntactic/eliminable (`to_checker`/`to_runtime` are total, idempotent, functions of the string alone — no claim about the program). **Ordinal↔canonical is essential/semantic** — it asserts two ordinals executed one statement, the gate exists to falsify it (274 FAILs of 1,363 on P26), and it is **many-to-one and run-relative** (`to_canonical` is a function of *(name, run)*). Conflating them would either delete an assumption the gate must test or keep paying for a rename that should not exist. **Seeds stay ordinal-named correctly** — the seed dict is an input to the Ruby runtime, which names by call order; a canonical key is a dead knob, and no run-independent canonical seed key exists.
**THE REAL RECURRING DEFECT:** not the asymmetry. Every `fix_len_names` docstring says it touches only `symbolic_vars[].name`/`events[].expr`; **in posts_show the docstring is FALSE** — the live body is `json.loads(_LEN_RE.sub(..., json.dumps(dump)))`, a whole-dump round trip, and `gate_canon.py:45-58` calls it, so on the gate path seed dicts come out **half-converted** to `SYM_LEN_<ordinal>_rows`, a third form neither consumer reads (**10.4 % of keys**). Notifications' in-place variant does not. One conversion silently applying to a field its sibling exempts, across 15 divergent bodies sharing one docstring.
**A SEVENTH incident, reframing the risk:** 2026-08-26, `canon()`'s docstring — declared exprs over list lengths never matched a dump and independences over them **PASSed as "mutually exclusive"**. A **false PASS**. "It only degrades conservatively" holds for today's known sites, not for the family.
**Options:** **C (a name type that hashes equal) is IMPOSSIBLE, not costly** — Python hashes the *query* object and JSON gives plain `str` keys, so every table AND query would need wrapping, destroying `NameSpace`'s genuine-absence distinction. **A (mint at source) needs B as a PRECONDITION** — coverage matches paths by string compare of `expr:taken`, so old `(len(X) == 0)` vs new `(SYM_LEN_X == 0)` splits one path into two signatures and silently doubles the tree; it also needs a Ruby-side shim for existing seed files. Corpora at stake: **~1,007,044 dumps, ~19.2 GB** (notifications 700,962; posts_show 234,257; four closed endpoints 71,825).
